Copy Constructor:
-----------------
	Copy Semantics. 
		Compiler provides copying semantics for any class. i.e I user does not provide copy constructor your code will work the same way as you overload(provide) your own copy constructor(user defined copy ctor).

	When do overload your copy constructor:
		Remember copy constructor is used when you initialize your object with object of its own type.
		Compiler provides copy semantics i.e., it helps to copy object of its own type without providing copy constructor.
		
		As long has you dont have pointer as a data member, you dont have to overload your copy constructor.
		
		If you have a pointer as a data member which involves dynamic memory allocation, this will result in a dangling pointer(an issue). 
	
		So the compiler provided copy constructor performs memberwise/bitwise/shallow copy of your objects. As long as not pointers are involved this is fine.
		
		When a pointer is involved, memberwise/bitwise /shallow copy results in dangling pointer. 
		
		Because of memberwise/bitwise copy which results in dangling pointer, which is called shallow copy.
	How do we handle it. 
		1. We provide our own copy constructor. Which inturn should handle separate memory allocation and copying the contents.
		
		When user define constructor provides the above mentioned operations (1. allocate new memory. 2. copying contents). Then such a copy constructor is referred to as deep copy.

	Static Variables in C and C++
		Static Members in a Class		
	
	Remember we discussed on static variables in C. i.e., variable can be local or global. It gets stored in data or bss segment of the memory.
	
	When it comes to C++, we can have a static member (data or function) of a class.
	We call such a member as a class member. i.e., to say one copy per class. This data member will be shared by all the objects of the class. 
		For example:
			class Employee{
				id, name, sal; //normal(instance) members 
				static string companyName;//declaration
			public:
				static string company(){ return companyName;}
			};
			
			
			string Employee::companyName = "Wipro Ltd";
			
			
	
		Instance members: --> one copy per object. 
		Class members: --> one copy per class.

		Friend Functions
		Friend Classes
------------------------------------------------------------
	When we talk about functions, we talk about members(instance member or class members ). There are non-members as in C++ (Global function/ members of another class). 
	
	Remember When we talk about data/function hiding(by having them in private), only members of the class can have access to it. Non-members are external functions cannot access private members directly.
	
	So we use friend keyword to introduce a function to a class so that we can access private members through object of the class.
	
	So to summarize:
		A friend function 
			a. is a non member function 
			b. can access private or protected members of that class. (By allowing your are breaking encapsulation(data hiding) intentionally and selectively).
